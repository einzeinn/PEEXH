# 05 — Personal Project Notes

## Why This Project

PEEXH was selected using a strict hackathon filter:

- narrow scope;
- one clear problem;
- specific target user;
- useful even if niche;
- easy interaction;
- clear reason to use voice;
- demonstrable in under three minutes.

## Internal Product Discipline

The project should resist common hackathon failure modes:
- solving too many problems;
- adding features for presentation value only;
- building infrastructure before validating the core loop;
- confusing technical complexity with product quality.

## Internal Rule

If a feature cannot clearly improve the core communication loop, safety, accessibility, personalization, or hackathon demonstration, it should not enter V1.

## Working Product Sentence

> **PEEXH learns to better understand how one person speaks, so that person can communicate their intended message more clearly.**
