# RFC-002 — Realtime Speech Streaming and AssemblyAI Integration

**Status:** Proposed  
**Type:** Feature / Architecture  
**Scope:** Frontend and Backend

---

## 1. Summary

This RFC specifies **Phase 1: Speech Foundation** for PEEXH. It establishes the end-to-end realtime audio streaming pipeline:
1. Accessible Tap-to-Talk audio capture on the frontend (16kHz 16-bit mono PCM).
2. Bi-directional WebSocket communication between frontend and backend.
3. Replaceable `SpeechTranscriber` interface on the backend.
4. AssemblyAI Realtime Speech-to-Text adapter with mock/simulation fallback for testing and development without live API keys.
5. Realtime transcript streaming back to the frontend with partial and final transcript events.

---

## 2. Motivation

PEEXH's core loop begins when a user with dysarthria speaks. To interpret intended meaning without forcing the user into unnatural interactions:
- Speech must stream in realtime with low latency.
- Audio capture must be accessible: one tap to start, one tap to stop (no hold-to-talk required).
- The backend must decouple the streaming protocol from AssemblyAI specifics via an interface (`SpeechTranscriber`) so the system remains testable and provider-replaceable.
- When an AssemblyAI API key is absent (e.g. in local development or automated CI), the system must cleanly fall back to a mock transcriber rather than crashing.

## 3. Architecture and Protocol Specification

### 3.1 High-Level Flow

```text
[Browser Mic (AudioWorklet/ScriptProcessor)]
    │
    │ Raw PCM 16kHz 16-bit Mono (binary frames) + JSON control messages
    ▼
[FastAPI WebSocket: /ws/speech]
    │
    │ Audio chunks passed to transcriber session
    ▼
[SpeechTranscriber Interface]
    ├─ AssemblyAITranscriber (WebSocket to wss://api.assemblyai.com/v2/realtime/ws)
    └─ MockSpeechTranscriber (Deterministic synthetic events for offline testing/demo)
    │
    │ Transcript events (partial / final / confidence)
    ▼
[FastAPI WebSocket: /ws/speech]
    │
    │ JSON transcript events
    ▼
[Frontend: Tap-to-Talk & Realtime Transcript Display]
```

### 3.2 WebSocket Event Contract

Endpoint: `/ws/speech`

#### Client -> Server Messages
- **Control JSON**:
  - `{"type": "start", "sample_rate": 16000}`: Initiates a transcription session.
  - `{"type": "stop"}`: Signals that speech has ended (tap-to-stop).
- **Audio Binary Frames**:
  - Binary frames containing 16-bit Linear PCM audio sampled at 16,000 Hz, single channel (mono), little-endian.

#### Server -> Client Messages
- `{"type": "session_started", "session_id": string, "provider": "assemblyai" | "mock"}`
- `{"type": "transcript", "text": string, "is_final": boolean, "confidence": float, "words": [...]}`
- `{"type": "speech_stopped"}`
- `{"type": "error", "message": string, "code": string}`

### 3.3 Backend Interfaces (`backend/app/assemblyai/`)
- `SpeechTranscriber` (Abstract Base Class):
  - `async def start(self) -> None`
  - `async def send_audio(self, chunk: bytes) -> None`
  - `async def stop(self) -> None`
  - Event callback registration for incoming transcripts and errors.
- `AssemblyAITranscriber`:
  - Connects to AssemblyAI Realtime WebSocket API using `ASSEMBLYAI_API_KEY`.
- `MockSpeechTranscriber`:
  - Simulates speech detection and emits realistic partial/final transcript events for development and testing.

### 3.4 Frontend Components (`frontend/src/components/speech/`)
- `useAudioRecorder` hook:
  - Accessible Web Audio API setup: 16kHz PCM stream capture using standard `AudioContext` and PCM conversion.
  - Microphone permission error handling and friendly recovery messages.
- `TapToTalkButton`:
  - Large primary control (min 80px target size for accessible motor control).
  - Clear state indicators: `Idle`, `Listening` (pulsing red indicator), `Processing`.
  - Accessible ARIA labels and keyboard triggering (Space / Enter).
- `TranscriptDisplay`:
  - Large, high-contrast readable typography for incoming partial and final transcripts.

## 4. Implementation Tasks Breakdown

To avoid hallucinations and maintain tight quality control, implementation will be executed in distinct sequential tasks:

### Task 1: Backend Domain Models and Protocol Schemas
- Define typed Pydantic models for WebSocket protocol messages (`backend/app/models/speech.py`):
  - `StartSessionMessage`, `StopSessionMessage`, `TranscriptEvent`, `SessionStartedEvent`, `ErrorEvent`.
- Unit test schemas and serialization.

### Task 2: Backend `SpeechTranscriber` Interface and Mock Transcriber
- Define `SpeechTranscriber` ABC in `backend/app/assemblyai/base.py`.
- Implement `MockSpeechTranscriber` in `backend/app/assemblyai/mock.py` for reliable testing without external API requirements.
- Unit test transcriber lifecycle and event propagation.

### Task 3: Backend AssemblyAI Realtime STT Adapter
- Implement `AssemblyAITranscriber` in `backend/app/assemblyai/adapter.py` connecting to AssemblyAI WebSocket (`wss://api.assemblyai.com/v2/realtime/ws`).
- Handle connection lifecycle, heartbeat, audio streaming, and transcript message parsing.
- Implement transcriber factory in `backend/app/assemblyai/factory.py` (selects `AssemblyAITranscriber` if `ASSEMBLYAI_API_KEY` is configured, otherwise falls back to `MockSpeechTranscriber`).

### Task 4: Backend WebSocket Endpoint `/ws/speech`
- Create WebSocket route in `backend/app/api/speech_ws.py`.
- Register route in `backend/app/main.py`.
- Write automated integration tests in `backend/tests/test_speech_ws.py` verifying connect, start, audio chunk ingestion, transcript broadcast, and stop.

### Task 5: Frontend Audio Capture and PCM Streaming Hook
- Create `frontend/src/lib/audio/pcm.ts` for browser audio conversion (resampling to 16kHz, 16-bit linear PCM little-endian buffer).
- Create `frontend/src/hooks/useSpeechStream.ts` managing WebSocket connection, audio recording, and event state.

### Task 6: Frontend Accessible Tap-to-Talk UI
- Implement accessible `TapToTalkButton` with large touch target and keyboard support.
- Implement `TranscriptView` with high-contrast, large typography for realtime partial and final transcripts.
- Integrate components into `frontend/src/app/page.tsx`.

### Task 7: End-to-End Verification & Changelog
- Verify backend tests pass (`pytest backend/tests`).
- Verify frontend builds cleanly (`npm run build`).
- Perform live manual test of Tap-to-Talk streaming over WebSocket.
- Update `docs/12-Changelog.md`.

---

## 5. Acceptance Criteria

1. `SpeechTranscriber` interface and adapter pattern implemented cleanly with zero hardcoded credentials.
2. Automated tests pass for WebSocket protocol and transcriber sessions.
3. Frontend provides accessible one-tap start and one-tap stop (no hold-to-talk requirement).
4. Audio streams from microphone as 16kHz PCM over WebSocket and returns realtime transcripts.
5. All code, comments, and schemas are strictly in English.
