# RFC-007 — Runtime Settings, Audio Input Selection, and Test Readiness

**Status:** Completed  
**Type:** Frontend / Runtime Configuration / Accessibility / Testing  
**Scope:** Frontend (`frontend/src/`), Audio Pipeline, Header & Settings Panel  
**Governing Phase:** Phase 6 — Runtime Settings & Test Readiness  

---

## 1. Summary

This RFC implements **Phase 6: Runtime Settings & Test Readiness** of the PEEXH roadmap. It introduces user-configurable runtime audio input controls and diagnostics, allowing users, developers, and evaluators to select any browser-visible audio input device and configure audio preprocessing.

The feature provides:
1. **Audio Input Device Selection**: Enumerating browser-visible `audioinput` devices (`navigator.mediaDevices.enumerateDevices()`) with a permanent "System Default" fallback.
2. **Audio Preprocessing Toggles**: Explicit runtime control over browser `echoCancellation`, `noiseSuppression`, and `autoGainControl` constraints.
3. **Local Persistence**: Client-side settings storage via versioned `localStorage` (`peexh.audio-settings.v1`) with corrupt-state resilience and reset-to-defaults capability.
4. **Speech Stream Hook Integration**: Refactoring `useSpeechStream` to dynamically apply active device and preprocessing constraints when opening the microphone stream.
5. **Runtime Diagnostics & Audio Level Meter**: Non-recording, real-time input level meter, microphone permission state detector, browser `AudioContext` sample rate monitor, target sample rate (16,000 Hz) readout, and backend reachability monitor.
6. **Accessible Settings Panel**: A WCAG 2.1 AAA compliant modal panel opened from the global header, supporting full keyboard navigation, visible focus, and large touch targets.

---

## 2. Motivation

In Phase 1–5, PEEXH captured audio using hardcoded browser constraints:
```typescript
audio: {
  channelCount: 1,
  echoCancellation: true,
  noiseSuppression: true,
  autoGainControl: true,
}
```

While appropriate for initial development, hardcoded constraints present major limitations for testing and real-world deployment:
1. **Loopback & External Speech Testing**: Testing PEEXH against dysarthric speech datasets played through another browser tab or software (e.g. YouTube, media players) requires routing audio through **Stereo Mix**, **VB-CABLE**, or virtual audio interfaces. Default noise suppression and echo cancellation aggressively filter out synthetic or loopback speech as "background noise".
2. **Microphone Hardware Diversity**: Users with motor disabilities often use specialized USB microphones, directional array mics, or wheelchair-mounted headsets. PEEXH had no mechanism to select these over the system-default webcam or laptop mic.
3. **Acoustic Diagnostic Feedback**: Without an input level meter, users cannot tell whether a quiet voice or misconfigured input device is transmitting audio before initiating an STT session.

> **Core Principle Alignment:**  
> *"The user should not have to adapt to the technology. The technology should adapt to the user."*  
> Giving users and evaluators full control over their audio input ensures accessibility and test readiness across all environments.

## 3. Scope and Non-Goals

### In Scope
- Client-side audio settings model (`selectedDeviceId`, `echoCancellation`, `noiseSuppression`, `autoGainControl`).
- Persistent storage in `localStorage` under `peexh.audio-settings.v1`.
- Audio device discovery, label resolution post-permission, and `devicechange` listener.
- Dynamic constraints injection in `useSpeechStream.startRecording()`.
- Accessible Settings button in `RootLayout` header and `SettingsPanel` modal.
- Realtime audio input level meter for testing (RMS/volume calculation, zero audio storage).
- Diagnostics display: permission state, device name, hardware sample rate, 16kHz target, backend `/health` status, active provider.
- Missing device handling: fallback to System Default without crashing.
- Unit and integration tests for settings, device discovery, and constraints generation.

### Out of Scope (Non-Goals)
- Direct browser-tab audio capture (no `getDisplayMedia()`).
- Direct system-audio capture bypassing OS audio inputs.
- Native OS audio drivers or desktop packaging.
- Recording, persisting, or exporting raw audio waveforms.
- Storing audio settings in Supabase or behind user authentication.
- Model switching, confidence thresholds, or backend agent policy configuration.
- RFC-008 Demo Mode buttons or video storyboard assets.

## 5. Technical Specification

### 5.1 Audio Settings Model (`frontend/src/types/audioSettings.ts`)

```typescript
export interface AudioSettings {
  selectedDeviceId: string | null; // null = System Default
  echoCancellation: boolean;
  noiseSuppression: boolean;
  autoGainControl: boolean;
}

export const DEFAULT_AUDIO_SETTINGS: AudioSettings = {
  selectedDeviceId: null,
  echoCancellation: true,
  noiseSuppression: true,
  autoGainControl: true,
};

export const AUDIO_SETTINGS_STORAGE_KEY = "peexh.audio-settings.v1";
```

### 5.2 Storage & Context (`frontend/src/context/AudioSettingsContext.tsx`)

- **Serialization**: JSON-encoded string in `localStorage`.
- **Validation**: Strict schema validation on parse. If corrupted or malformed, fallback to `DEFAULT_AUDIO_SETTINGS` without throwing exceptions.
- **SSR Safety**: Guards against `typeof window === "undefined"`.
- **Reset Action**: `resetToDefaults()` restores initial default values.

### 5.3 Audio Device Discovery Hook (`frontend/src/hooks/useAudioDevices.ts`)

- Queries `navigator.mediaDevices.enumerateDevices()`.
- Filters devices strictly where `device.kind === "audioinput"`.
- Adds `{ deviceId: "", label: "System Default" }` at the beginning of the list.
- Fallback labels: if `device.label` is empty (before microphone permission granted), names entries `"Microphone 1"`, `"Microphone 2"`, etc.
- Listens to `devicechange` events on `navigator.mediaDevices` to dynamically refresh the list when headsets/cables are connected or removed.
- Validates current `selectedDeviceId`: if the selected device disappears from the list, automatically falls back to `null` (System Default).

### 5.4 Speech Stream Integration (`frontend/src/hooks/useSpeechStream.ts`)

Refactor `startRecording()` to compute constraints from active settings:

```typescript
const constraints: MediaStreamConstraints = {
  audio: {
    deviceId: settings.selectedDeviceId
      ? { exact: settings.selectedDeviceId }
      : undefined,
    channelCount: 1,
    echoCancellation: settings.echoCancellation,
    noiseSuppression: settings.noiseSuppression,
    autoGainControl: settings.autoGainControl,
  },
};

let stream: MediaStream;
try {
  stream = await navigator.mediaDevices.getUserMedia(constraints);
} catch (err) {
  // If exact deviceId fails (OverconstrainedError), fallback to system default
  if (settings.selectedDeviceId) {
    stream = await navigator.mediaDevices.getUserMedia({
      audio: {
        channelCount: 1,
        echoCancellation: settings.echoCancellation,
        noiseSuppression: settings.noiseSuppression,
        autoGainControl: settings.autoGainControl,
      },
    });
  } else {
    throw err;
  }
}
```

### 5.5 Settings UI Components

1. **Header Trigger Button (`frontend/src/components/settings/SettingsButton.tsx`)**:
   - Clean gear icon button with `aria-label="Open Audio & Runtime Settings"`.
   - Placed in `RootLayout` header next to system branding.
2. **Modal Dialog (`frontend/src/components/settings/SettingsPanel.tsx`)**:
   - `role="dialog"`, `aria-modal="true"`, `aria-labelledby="settings-dialog-title"`.
   - Keyboard trap and `Escape` key close handler.
   - Dropdown for Audio Input Device selection.
   - Toggles with explicit visual ON/OFF states for Echo Cancellation, Noise Suppression, and Auto Gain Control.
   - Diagnostics section:
     - Active microphone permission state (`granted`, `prompt`, `denied`, or `unavailable`).
     - Browser `AudioContext` sample rate (e.g. 44,100 Hz / 48,000 Hz).
     - PEEXH stream target: 16,000 Hz (downsampled).
     - Backend status indicator (reachable / unreachable).
     - Active provider (AssemblyAI / Mock / Session not started).
   - "Reset to Defaults" action button.
3. **Input Level Meter (`frontend/src/components/settings/AudioInputMeter.tsx`)**:
   - Test Input button to open a brief diagnostic stream using selected settings.
   - Computes RMS volume level via `AnalyserNode.getByteFrequencyData()`.
   - Renders a responsive, accessible green/yellow meter bar.
   - Zero audio frames stored or transmitted. Automatically cleans up track on close.

## 6. Accessibility & Human Factors

1. **Touch Targets**: All toggle buttons, selects, and close buttons maintain a minimum touch target of $48\text{px} \times 48\text{px}$.
2. **Keyboard Navigation**:
   - Focus moves into the modal on open.
   - `Escape` closes the panel and returns focus to the header trigger button.
   - Tab navigates cleanly across all interactive elements.
3. **Visual Feedback**: High-contrast toggles (`#4F46E5` active, slate-300 inactive) with text labels ("Enabled" / "Disabled") alongside switch indicators.
4. **Error Messaging**: Clear, non-technical plain English explanations when microphone permission is denied or a device is disconnected.

## 8. Manual Test Checklist

- [ ] **TEST A — Default Microphone**:
  Select "System Default". Click Speak. Verify speech is captured and transcribed normally.
- [ ] **TEST B — Alternate Physical Microphone**:
  Connect an external USB mic or headset. Select it in Settings. Verify audio streams from the selected hardware.
- [ ] **TEST C — Loopback / Stereo Mix / Virtual Cable**:
  Play speech audio in another browser tab. Select Stereo Mix or VB-CABLE as audio input. Disable Echo Cancellation, Noise Suppression, and Auto Gain Control. Click Speak. Verify raw synthetic/loopback speech is cleanly recognized by AssemblyAI without acoustic filtering.
- [ ] **TEST D — Preprocessing Comparison**:
  Run an audio sample with preprocessing toggles ON vs OFF. Verify the stream respects the settings.
- [ ] **TEST E — Persistence**:
  Change input device and disable Noise Suppression. Refresh browser. Verify settings persist from `localStorage`.
- [ ] **TEST F — Missing Device Fallback**:
  Select a removable USB mic. Unplug the device. Verify PEEXH gracefully falls back to System Default without crashing.
- [ ] **TEST G — Permission Denial**:
  Block microphone permission in browser site settings. Open PEEXH. Verify accessible error notice and diagnostics indicate "Permission Denied".

## 9. Acceptance Criteria

1. **Audio Input Device Discovery**: `navigator.mediaDevices.enumerateDevices()` discovers all `audioinput` devices with a persistent System Default option.
2. **Preprocessing Controls**: Toggling Echo Cancellation, Noise Suppression, or Auto Gain Control modifies the active `getUserMedia()` constraints.
3. **Device Disappearance Resilience**: Disconnecting a selected input device automatically falls back to System Default without unhandled runtime exceptions.
4. **Persistent Configuration**: Settings survive full page reload via `peexh.audio-settings.v1`. Corrupted storage safely recovers to default values.
5. **Input Level Diagnostics**: Realtime input meter reflects audio activity without recording or persisting audio.
6. **Accessibility Standard**: Full keyboard navigation, visible focus rings, and $\ge 48\text{px}$ touch targets across the settings UI.
7. **Production Build & Tests**: Clean `npm run build` and all backend tests (64/64) continue to pass.
8. **Language**: All UI text, logs, code, tests, and documentation are strictly in English.
