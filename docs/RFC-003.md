# RFC-003 — PEEXH Agent Core and LLM Interpretation Engine

**Status:** Implemented
**Type:** Architecture / Feature  
**Scope:** Backend and Frontend Integration  
**Governing Phase:** Phase 2 (Agent MVP)

---

## 1. Summary

This RFC implements **Phase 2: Agent MVP** for PEEXH. It introduces:
1. The **PEEXH Agent State Machine** (`backend/app/agent/`) governing explicit conversation states.
2. A provider-independent **LLM Interpreter Abstraction** (`backend/app/llm/`) producing structured candidate interpretations from raw dysarthric speech transcripts.
3. A **Deterministic Confidence Scorer** (`backend/app/scoring/`) enforcing the product principle:
   > *"LLM interprets. PEEXH decides. User controls."*
4. Seamless integration with the existing `/ws/speech` pipeline so that upon final speech transcription, PEEXH evaluates the utterance and returns an authoritative `agent_decision` event (`PROPOSE_PHRASE`, `SHOW_CANDIDATES`, or `REQUEST_REPEAT`).

---

## 2. Motivation

Raw Speech-to-Text (STT) frequently misrecognizes or truncates dysarthric speech due to altered resonance, consonant imprecision, and irregular pauses. 

However, speech context and linguistic patterns often contain enough signal to infer the intended message. An LLM is well-suited to generate likely candidate phrases, but an LLM must **never** be allowed to autonomously decide confidence or speak unverified guesses.

PEEXH separates these duties:
- **LLM**: Generates candidate intended phrases and syntactic variations.
- **Scorer (Deterministic)**: Weighs STT acoustic confidence, candidate consistency, and scoring margins to classify confidence into `HIGH`, `MEDIUM`, or `LOW`.
- **PEEXH Agent**: Enforces the action contract (`PROPOSE_PHRASE`, `SHOW_CANDIDATES`, `REQUEST_REPEAT`).

## 3. Technical Specification

### 3.1 Domain Models (`backend/app/models/agent.py`)

- **ConfidenceLevel**: `Enum("HIGH", "MEDIUM", "LOW")`
- **AgentAction**: `Enum("PROPOSE_PHRASE", "SHOW_CANDIDATES", "REQUEST_REPEAT", "COMMUNICATE", "LEARN_CORRECTION")`
- **PhraseCandidate**:
  - `text: str` — candidate intended phrase
  - `confidence: float` — model-assigned candidate probability (0.0 - 1.0)
  - `explanation: Optional[str]` — brief rationale for interpretation
- **InterpretationResult**:
  - `raw_transcript: str`
  - `stt_confidence: float`
  - `candidates: List[PhraseCandidate]`
- **AgentDecision**:
  - `type: Literal["agent_decision"] = "agent_decision"`
  - `action: AgentAction`
  - `confidence_level: ConfidenceLevel`
  - `overall_confidence: float`
  - `primary_phrase: Optional[str]`
  - `candidates: List[PhraseCandidate]`
  - `reason: str`

### 3.2 Deterministic Confidence Scorer (`backend/app/scoring/scorer.py`)

Confidence is calculated mathematically outside the LLM:
$$\text{Score} = w_{\text{stt}} \cdot C_{\text{stt}} + w_{\text{llm}} \cdot C_{\text{top\_candidate}} + \text{margin\_bonus}$$

- If top candidate confidence $\ge 0.80$ (configurable via `PEEXH_HIGH_CONFIDENCE_THRESHOLD`) and $C_{\text{stt}} \ge 0.50$ (configurable via `PEEXH_MIN_STT_CONFIDENCE_FOR_HIGH`):
  - Level = `HIGH`
  - Action = `PROPOSE_PHRASE`
- If composite confidence is between $0.45$ and $0.80$:
  - Level = `MEDIUM`
  - Action = `SHOW_CANDIDATES` (presents top 2–3 candidates)
- If composite confidence $< 0.45$ (`PEEXH_LOW_CONFIDENCE_THRESHOLD`) or transcript is empty/indecipherable:
  - Level = `LOW`
  - Action = `REQUEST_REPEAT` (refuses to guess; asks user to speak again)

### 3.3 LLM Interpreter Abstraction (`backend/app/llm/`)

- `Interpreter` (ABC):
  ```python
  async def interpret(
      self,
      transcript: str,
      stt_confidence: float,
      context: Optional[dict] = None,
  ) -> InterpretationResult: ...
  ```
- `MockInterpreter`:
  - Recognizes common dysarthric speech patterns (e.g. phoneme omissions like "wat-er" -> "I need water", "hel-p" -> "Can you help me", "doc-tor" -> "I need to see a doctor").
  - Provides deterministic, reproducible test scenarios for High, Medium, and Low confidence without requiring paid API tokens.
- `CloudLLMInterpreter`:
  - Uses OpenAI / Anthropic / Gemini API via structured JSON outputs when `LLM_API_KEY` is provided.
- `get_interpreter(settings)`:
  - Factory pattern resolving to cloud adapter if `LLM_API_KEY` is set, else `MockInterpreter`.

### 3.4 Agent State Machine (`backend/app/agent/`)

States:
- `IDLE`: Waiting for user activation.
- `LISTENING`: Realtime audio incoming.
- `INTERPRETING`: LLM generates candidate phrases.
- `DECIDING`: Scorer evaluates confidence and assigns action.
- `AWAITING_CONFIRMATION`: Waiting for user selection/confirmation (Phase 3).
- `CONFIRMED`: Final message ready to communicate (Phase 3).

### 3.5 WebSocket Protocol Enhancement

When speech stops on `/ws/speech`, the backend automatically invokes the agent on the final transcript and transmits the `AgentDecision` event directly to the client:
```json
{
  "type": "agent_decision",
  "action": "PROPOSE_PHRASE",
  "confidence_level": "HIGH",
  "overall_confidence": 0.86,
  "primary_phrase": "I need some water",
  "candidates": [
    {
      "text": "I need some water",
      "confidence": 0.88,
      "explanation": "Interpreted from 'need watah' with high phonetic match"
    },
    {
      "text": "I need a drink",
      "confidence": 0.52,
      "explanation": "Semantic alternative"
    }
  ],
  "reason": "Top candidate confidence exceeds high threshold (0.80)"
}
```
